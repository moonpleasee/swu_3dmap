# 西大云游 · 仅展示版部署交接

更新：2026-11-14。面向负责用户现有网站的部署 AI，以本文件及当前源码为准。

## 1. 本次任务与分工

用户已有域名，也已有另一个 AI 正在开发的网站。现在需要将“西大云游”作为其中的校园地图模块接入。

- 本项目开发 AI：继续负责地图、界面、模型、交互功能和相关代码修改。
- 你（整站部署 AI）：负责现有网站的集成入口、托管、路由、域名、HTTPS、发布、回滚与线上验收。
- 需要本模块源码适配时，将现有技术栈、目标URL、限制和接口要求交给开发AI；避免双方同时覆盖源文件。

**用户当前只要展示功能。不要开放社区，也不要为本次发布额外开通数据库、图片存储、短信或内容审核等服务。**

## 2. 当前功能边界

保留：
- 三维校园地图、已有建筑、地形、道路与绿地。
- 地图旋转、缩放、搜索、分类、建筑资料、单栋查看和现有场景工具。
- 统一手机竖屏界面，电脑以9∶16比例、最大430像素宽居中预览，窗口较矮时等比缩小。
- 初始全景不显示楼名气泡，放大后逐步显示。
- 建筑详情里的讨论区域显示 **“暂不开放”**。

暂时关闭：登录注册、上传照片、评论回复、评分、创建社区地点、名称建议提交及社区管理入口。

社区源码和历史数据保留，后端默认开关 `COMMUNITY_ENABLED=0`，不设也关闭。若运行后端，其社区API会拒绝访问。不得因为社区代码仍存在就认为应启用；恢复功能需用户后续明确要求。

## 4. 推荐部署方式：作为静态模块发布

本次仅展示可直接托管生产构建目录 **`dist/`**。浏览器负责渲染3D，不需要社区Node服务运行在云端。

构建机使用Node.js 24，在项目根目录运行：

```bash
npm ci
npm run build
```

Windows使用 `npm.cmd`。随后将 **dist内部全部文件与目录** 发布到目标静态目录，保留层级，尤其不要遗漏 `assets/` 和 `data/`。不要只上传index.html。

正式环境不使用 `npm run dev` 或Vite开发服务器。静态发布完成后，访问者不依赖开发者电脑在线。

原网站如果已有可用的静态托管空间，可复用其托管与域名；是否增加费用取决于原平台的流量、容量和套餐，不承诺所有平台都免费。已有域名不等于已经有可运行Node服务的主机，但本次静态方案不要求新增这种主机。

## 5. 三种接入方式，优先选择前两种

以下域名仅为占位示例，不是用户真实域名。

### A. 原网站导航链接到地图子域名

例如主站 `https://www.example.cn`，地图 `https://map.example.cn/`。

- 子域名静态根目录放dist内容，主站添加“西大云游 / 校园地图”入口。
- 部署AI负责DNS、HTTPS和托管绑定。
- 地图与原站路由隔离，最少干扰现有网站。
- 这叫接入入口，不是自动统一账号；当前展示版也不需要账号。

### B. 放在原域名子目录

例如 `https://www.example.cn/campus/`。

- 将dist内容放在独立的campus目录，主站增加跳转入口。
- 当前Vite `base: './'`，地图数据使用 `BASE_URL` 相对加载；必须实际检查资源请求是否落在 `/campus/assets/`、`/campus/data/`。
- `/campus` 应重定向到 `/campus/`，保留尾部斜线，以免相对资源解析到错误位置。
- 该目录由静态服务处理，不能被主站SPA兜底改写为主站index.html；主站路由也不要把地图hash当作自己的业务路由。
- 地点链接示例：`/campus/#place=843421786`。hash不需要服务端路由。
- 如果原网站部署工具不保留子目录或改写相对路径，请记录实际请求地址，交开发AI做base适配，不要重写地图模块。

### C. 在原网站页面中用iframe展示

可考虑 `iframe src="/campus/"`，由主站给它足够的高度和手机端空间，建议采用同源子目录。

- 先验收地图能独立访问，再做iframe，分别检查触摸、页面滚动、手机键盘、全屏及布局。
- frame-src、frame-ancestors、X-Frame-Options必须与实际父站和地图origin匹配。
- 若用本项目Node后端，Helmet默认防跨origin嵌入；不同子域也算不同origin。静态托管则由原托管平台决定响应头。
- 需要跨origin iframe时，把确切父站origin交开发AI配置允许名单；不要直接删除全部安全头或配置任意站点可嵌入。

## 6. 当前展示模式与API探测的注意点

当前前端启动时仍会探测根路径 **`/api/health`**：
- 返回 `communityEnabled: false`，或API不存在/返回非JSON时，进入仅展示模式。
- 无社区后端时地图仍可展示；一次探测404不表示地图数据加载失败。
- 如果主站已有 `/api/health`，不要覆盖它，更不要将主站整个 `/api` 指向地图服务。检查其响应不会误返回 `communityEnabled: true`。
- 若希望展示版完全不请求API、减少控制台404，或原站已有相冲突的健康接口，请把此约束交开发AI增加强制展示构建开关；当前尚无 `VITE_DISPLAY_ONLY` 之类的构建变量，不能只设置一个不存在的变量就声称完成适配。

默认Compose已将 `COMMUNITY_ENABLED` 设为0。如果继续复用本项目Node服务，请保持0；但单纯静态发布无需启动Compose、Caddy或社区数据库。

## 7. 交付文件、数据保护和版本管理

### 静态发布需要

`dist/` 内全部内容。域名、HTTPS、路由和缓存由部署AI接入现有站点。

### 若部署系统自行构建，需要源码

`package.json`、`package-lock.json`、`index.html`、`vite.config.js`、`src/`、`public/`、`scripts/pack-dist-data.mjs`。在目标构建环境执行npm ci。构建会精简 dist/data 的 JSON，页面读取时还原，整个 dist 应作为同一版本发布。

### 不应作为公开静态内容发布

`.env`、`server-data/`、SQLite及其WAL/SHM文件、备份、node_modules、work、视频outputs、Git元数据、管理员密码和云密钥。

后端和管理脚本可留在源码仓库，但本次无需启动。既有数据库与照片不要删除，也不要将开发机测试库覆盖服务器正式库。建筑ID、地形与名称数据不可在部署时重新生成。

每次更新应记录源码版本/提交、构建时间、发布目录和可回退版本。以仓库main分支的已提交源码构建，仓库为Private时部署方需有读取权限。授权和第三方署名见LICENSE及NOTICE.md，静态分发中保留THIRD-PARTY-NOTICES.txt。

## 8. 缓存、更新与回滚

- HTML使用较短缓存或协商缓存；带哈希的assets可长缓存，但上传顺序应保证新HTML引用的文件已到位。
- 更新data目录时确认缓存刷新，否则页面可能拿到旧地图数据。
- 保留上一版静态发布目录，优先原子切换目录或使用托管平台版本发布；避免覆盖一半导致资源404。
- 失败时回切上一版静态包和路由配置，不回滚/删除用户数据库。
- 原网站与地图分别验收，不为修地图而清空原站目录或替换原站首页。

## 9. 部署前从你负责的现有项目中确认

先查现有配置，避免让用户重复提供已存在的信息：

1. 真实域名和托管平台，主站技术栈与发布方式。
2. 使用子域名入口、同域子目录，还是iframe；推荐先选A或B。
3. 主站现有路由、健康接口、响应头和缓存规则。
4. 是否能直接托管静态目录，是否有体积/流量限制。

域名和原站托管细节在本项目中尚未提供，不能假定它们已具备某种服务器、备案或证书配置。本次没有操作域名或现有线上网站。静态展示不自动免除原站适用的接入要求；相关确认由整站部署方结合原站办理情况处理。

## 10. 上线验收清单

- 原网站首页、导航、现有接口均正常。
- “校园地图”入口能到正确地图URL，HTTPS正常。
- assets/data请求无错误；WebGL正常显示全部校园。
- 手机及电脑均采用手机布局，无横向溢出。
- 初始全景无楼名气泡，放大后逐渐出现；搜索和点击建筑正常。
- 讨论显示“暂不开放”；没有登录、上传、评分、名称建议或创建地点的可提交入口。
- 刷新带地点hash的链接仍能加载对应建筑。
- 若iframe接入，独立访问和内嵌两种形式均通过触摸、滚动、全屏检查。
- 关闭开发者电脑后，托管站点仍能访问。
- 已记录线上URL、发布版本、部署配置、验收结果与回退方法。

开发侧已有：生产构建通过；`scripts/preview-display-only.mjs` 检查手机/桌面仅展示和后端写入关闭，证据位于 `work/display-only/`。此记录不是线上验收，部署AI需对真实地址重新检查。
